# PakCash V8.2 Changelog

## Forensic/security repairs

- Added V8.2 independent forensic audit.
- Added safe V7/V8 wallet opening-balance migration.
- Added authoritative `app_settings`.
- Added wallet, referral, and withdrawal reconciliation functions.
- Added case-insensitive username uniqueness.
- Added exactly-one-active-daily-spin enforcement.
- Hardened daily-spin configuration and Pakistan calendar-day handling.
- Withdrawal eligibility now derives verified referrals from authoritative referral rows.
- Referral verification requires active accounts and confirmed email.
- Added referral-count synchronization trigger.
- Removed any implication that referral verification itself creates a financial reward.
- Hardened event slug lifecycle.
- Added shared dynamic event route for admin-created events.

## Frontend

- Added real mobile navigation.
- Removed inline JavaScript and inline styles where they weakened CSP.
- Removed inline `onclick` handlers.
- Added accessible status messaging.
- Added safer admin DOM rendering.
- Removed admin `prompt()`/`alert()` workflows.
- Added wallet/withdrawal lifecycle details.
- Improved share/copy failure handling.
- Added inactive-event action handling.
- Added Urdu RTL direction handling.
- Added SEO descriptions/canonicals/noindex controls.
- Added sitemap.
- Removed Supabase SDK from static legal/support pages.

## Advertising

- Centralized existing ad slots in `js/ads.js`.
- Separated advertising from rewards.
- Removed direct provider snippets from individual pages.

## Deployment

- Added `worker.js` for runtime security headers.
- Added `wrangler.toml` for Workers Static Assets.
- Added conservative HTML/asset cache behavior.
- Pinned Supabase JS to 2.111.0.

## Explicitly not added

- No fake balances.
- No fake referrals.
- No fake withdrawals.
- No fake task completions.
- No fake ad rewards.
- No fabricated fraud detection.
- No fabricated payment-provider integration.
