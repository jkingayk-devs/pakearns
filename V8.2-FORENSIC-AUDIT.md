# PakCash V8.2 Forensic Audit

This audit was performed independently against the supplied V8.1 project source. The previous V8.1 audit/report was not used as proof of correctness.

## Findings

### F-001 — CRITICAL — Database migration/data integrity
**File:** `database-migrations/001_core.sql`, `004_v81_reconciliation.sql`

**Problem:** Existing V7 wallet balances could exist without corresponding immutable ledger opening entries. A reconciliation could therefore report a mismatch even though the real wallet contained funds.

**Impact:** incorrect balance/reconciliation; possible payout eligibility errors; migration/data-integrity risk.

**V8.2 fix:** migration `005_v82_product_hardening.sql` creates an auditable `opening_balance` transaction for existing wallets that have no ledger history. Existing ledgers that disagree with wallet state cause migration failure instead of silent rewriting.

---

### F-002 — CRITICAL — Daily-spin configuration multiplicity
**File:** `database-migrations/003_rls_and_seed.sql`, `002_security_and_functions.sql`

**Problem:** The previous implementation selected the first active daily-spin task rather than guaranteeing exactly one active configuration.

**Impact:** incorrect reward configuration and eligibility.

**V8.2 fix:** a preflight migration check plus partial unique index allow exactly one active `daily_spin`; the RPC also verifies the count.

---

### F-003 — CRITICAL — Cached referral count could drift
**File:** `profiles.verified_referrals`, referral verification RPC

**Problem:** A stored counter could theoretically disagree with the authoritative referral rows.

**Impact:** incorrect payout eligibility.

**V8.2 fix:** withdrawal eligibility now counts eligible verified referrals from authoritative rows; a trigger keeps the cached profile count synchronized; reconciliation RPC exposes drift.

---

### F-004 — CRITICAL — Referral verification was too permissive
**File:** `admin_verify_referral`

**Problem:** Verification did not require the referred account to be active and email-confirmed.

**Impact:** abuse and incorrect eligibility.

**V8.2 fix:** verification requires active referrer, active referred account, and `auth.users.email_confirmed_at`.

---

### F-005 — HIGH — Business rules duplicated in UI and SQL
**File:** withdrawal UI and withdrawal RPC

**Problem:** minimum, maximum, daily limit, and referral requirement were hardcoded in multiple places.

**Impact:** maintenance drift and misleading UX.

**V8.2 fix:** authoritative `app_settings` table; the server reads it, and the UI reads the same configuration.

---

### F-006 — HIGH — Mobile navigation was hidden
**File:** `css/app.css`

**Problem:** the V8.1 mobile media query used `.nav{display:none}` without a replacement control.

**Impact:** broken mobile UX/navigation.

**V8.2 fix:** accessible Menu toggle with keyboard/focus support and responsive dropdown navigation.

---

### F-007 — HIGH — Admin XSS surface
**File:** `admin/index.html`

**Problem:** database values were interpolated into `innerHTML` strings.

**Impact:** potential stored XSS if malicious database content reached admin UI.

**V8.2 fix:** admin UI was rewritten with DOM APIs and `textContent` for database values.

---

### F-008 — HIGH — Admin used `prompt()`/`alert()` for financial actions
**File:** `admin/index.html`

**Problem:** important financial actions depended on browser prompts and generic alerts.

**Impact:** poor UX/accessibility and weak action context.

**V8.2 fix:** persistent notes/reference fields, explicit confirmations, and status messaging.

---

### F-009 — HIGH — Security headers depended on `_headers` only
**File:** `_headers`

**Problem:** `_headers` is not itself a Worker runtime implementation for a `workers.dev` deployment.

**Impact:** production security headers could be absent depending on deployment mode.

**V8.2 fix:** added `worker.js` and `wrangler.toml` that apply equivalent security headers at runtime. `_headers` remains for Pages-style deployment.

---

### F-010 — HIGH — CSP required `unsafe-inline`
**File:** `_headers`

**Problem:** inline scripts/styles prevented a strict script/style policy.

**Impact:** weaker XSS defense.

**V8.2 fix:** moved inline application scripts to external files and removed `unsafe-inline` from CSP.

---

### F-011 — HIGH — Supabase SDK was floating
**File:** HTML pages

**Problem:** `@supabase/supabase-js@2` allowed the CDN to resolve a moving version.

**Impact:** uncontrolled dependency changes.

**V8.2 fix:** pinned the CDN to Supabase JS 2.111.0, verified against the current jsDelivr/npm package listings at audit time. citeturn0search1turn0search6

---

### F-012 — HIGH — Profile lookup failure could fail open
**File:** `js/auth.js`

**Problem:** a profile query error could previously leave a valid session treated as authenticated.

**Impact:** incorrect account state/UX and potential authorization confusion.

**V8.2 fix:** profile lookup errors or missing profiles now sign out and fail closed.

---

### F-013 — MEDIUM — Withdrawal history omitted refund/rejection details
**File:** `withdraw.html`

**Problem:** users could not see the complete lifecycle information.

**Impact:** support/UX problems.

**V8.2 fix:** ID, review/paid/refunded timestamps, payment reference, and reason are displayed.

---

### F-014 — MEDIUM — Event pages were not SEO-specific
**File:** `events/*/event.html`

**Problem:** every event used `Event — PakCash` and lacked descriptions/canonicals.

**Impact:** poor SEO and discoverability.

**V8.2 fix:** static event routes now have meaningful metadata and canonicals; runtime metadata is also updated from database data.

---

### F-015 — MEDIUM — Admin-created event could have no route
**File:** event architecture/admin

**Problem:** arbitrary database events had no corresponding static directory.

**Impact:** broken deployment/navigation.

**V8.2 fix:** added shared `/events/event.html?slug=...` route. Existing published slugs are immutable so existing URLs do not silently break.

---

### F-016 — MEDIUM — Inactive events exposed action links
**File:** `js/event.js`

**Problem:** inactive event pages still presented registration/task actions.

**Impact:** misleading UX.

**V8.2 fix:** inactive event actions are hidden.

---

### F-017 — MEDIUM — Ad configuration was inconsistent
**File:** `js/ads.js`, page HTML

**Problem:** the old JS claimed Adsterra while pages directly embedded multiple provider domains.

**Impact:** maintenance confusion and inconsistent third-party loading.

**V8.2 fix:** ad URLs/slots are centralized in `js/ads.js`; pages only declare slots. Ads remain independent from reward logic.

---

### F-018 — MEDIUM — Legal/support pages unnecessarily loaded Supabase
**File:** legal/support HTML

**Problem:** static informational pages loaded the database SDK/config without needing it.

**Impact:** unnecessary bandwidth and third-party dependency surface.

**V8.2 fix:** removed Supabase dependencies from static legal/support pages.

---

### F-019 — MEDIUM — Password policy was only eight characters
**File:** registration/reset forms

**Problem:** V8.1 only enforced eight characters client-side.

**Impact:** weaker account security.

**V8.2 fix:** UI requires 10 characters; Supabase Auth password policy must still be configured in the dashboard because the frontend is not an authority for Auth policy.

---

### F-020 — MEDIUM — Daily-spin calendar boundary used UTC
**File:** `claim_daily_spin`, task UI

**Problem:** daily eligibility could reset at UTC midnight rather than the intended Pakistan calendar day.

**Impact:** confusing task timing.

**V8.2 fix:** database and UI use `Asia/Karachi` calendar dates.

---

### F-021 — MEDIUM — Static event/referral navigation could lose referral parameter
**File:** events navigation

**Problem:** the referral query parameter was preserved on some event links but could be lost when the user selected Register directly from the event list.

**Impact:** referral attribution loss.

**V8.2 fix:** event-list registration links preserve the validated query parameter. Server-side validation remains authoritative.

---

### F-022 — MEDIUM — Admin task UI could imply unsupported task engines
**File:** admin task configuration

**Problem:** unsupported task types were configurable despite lacking verification engines.

**Impact:** misleading reward UI/abuse risk.

**V8.2 fix:** unsupported types may only be stored inactive; only daily spin can be active/rewardable.

---

### F-023 — MEDIUM — Admin event slug edits could break URLs
**File:** `admin_set_event`

**Problem:** changing an existing slug could orphan published links.

**Impact:** broken deployment/navigation.

**V8.2 fix:** existing slugs are immutable.

---

### F-024 — LOW — Raw internal errors were displayed in several production paths
**File:** previous UI handlers

**Problem:** database error text could leak implementation details to users.

**Impact:** UX/security information disclosure.

**V8.2 fix:** user-facing financial/auth errors are normalized; admin status surfaces remain more descriptive for operators.

---

### F-025 — LOW — Clipboard/share failures had poor feedback
**File:** `js/app.js`

**Problem:** clipboard failure could produce a browser exception or generic alert.

**Impact:** mobile UX.

**V8.2 fix:** share/copy failures use non-blocking status feedback.

---

### F-026 — LOW — Static inline handlers reduced CSP strength
**File:** multiple HTML pages

**Problem:** `onclick` handlers were present in the prior build.

**Impact:** CSP maintenance and testability.

**V8.2 fix:** delegated external event handling via `ui.js`.

---

### F-027 — LOW — Business/legal page SEO metadata was incomplete
**File:** public HTML pages

**Problem:** descriptions/canonicals were missing broadly.

**Impact:** SEO quality.

**V8.2 fix:** public pages receive descriptions and canonical metadata where appropriate; private/admin/auth pages are `noindex`.

---

### F-028 — LOW — Deployment cache behavior was unspecified for Workers
**File:** deployment

**Problem:** static assets and HTML had no explicit Worker cache policy.

**Impact:** stale deployments/asset behavior.

**V8.2 fix:** Worker runtime applies conservative cache behavior: version-independent assets cache for one day; HTML is `no-store`.

---

### F-029 — LOW — No verified advanced fraud engine exists
**Area:** abuse prevention

**Problem:** referral abuse beyond basic graph/account validation was not implemented.

**Impact:** abuse risk.

**V8.2 action:** no fake fingerprint/IP detection was added. V8.2 documents this as an operational gap requiring Cloudflare/Supabase controls or a dedicated fraud service.

---

### F-030 — LOW — No live payment-provider integration exists
**Area:** withdrawals

**Problem:** marking a withdrawal paid records an admin payment reference but does not call Easypaisa/JazzCash/bank APIs.

**Impact:** operational dependency.

**V8.2 action:** intentionally not fabricated. The payout operator must perform the external payment and then record the reference.

## Unresolved external-environment items

These cannot be honestly verified from a static ZIP:

- live Supabase RLS isolation between two real accounts
- live concurrent RPC execution against PostgreSQL
- Supabase Auth email delivery/confirmation
- Cloudflare Worker runtime behavior after deployment
- external ad-provider rendering
- external payment-provider execution
- production bot/rate-limit effectiveness
- real mobile browser rendering on physical devices
